## 二、我想改 X，该动哪个文件

**这是最常用的一张表。**

| 想改什么 | 改这里 |
|---|---|
| 页面上的文字（About / Brand / 首页） | `src/content/` 下对应文件，每个文件里分 `en` 和 `fr` 两块 |
| 导航栏、按钮、小标题这类界面文字 | `src/i18n/ui.ts` |
| 赛事日期 / 地点 | `src/content/events.ts` |
| 品牌颜色、字体、字号 | `src/styles/global.css` 顶部的 `@theme` 区块 |
| 导航栏有哪几项 | `src/config/site.ts` 的 `nav` |
| 公司名、所在地、联系邮箱 | `src/config/site.ts` |
| 页面的排版结构 | `src/components/pages/` 下的三个文件 |
| 页头 / 页脚 | `src/components/Header.astro`、`Footer.astro` |
| GAG 标识图形 | `src/components/GagLogo.astro`（矢量，不是图片）|
| 网页标签图标 | `public/favicon.svg` |

### 常见操作

**改一句文案** → 找到 `src/content/` 里的那句话，直接改。**注意 `en` 和 `fr` 两处都要改**，否则会出现一种语言更新了、另一种没更新。

**加一场赛事** → 在 `src/content/events.ts` 的 `events` 数组里加一项，英法文各填一份。数组为空时首页会自动显示「新赛季赛程即将公布」，不会留一个空框。

**填上联系邮箱** → 改 `src/config/site.ts` 里的 `contactEmail`，从 `null` 改成真实邮箱。首页「合作与赞助」那里的按钮会自动出现（现在显示的是「联系方式即将公布」）。

**加一个新页面**（比如「组织架构」）：
1. 在 `src/components/pages/` 新建页面组件，接收 `lang` 参数
2. 在 `src/pages/` 和 `src/pages/fr/` 各建一个 2 行的路由文件
3. 在 `src/i18n/ui.ts` 加上导航文字（英法各一条）
4. 在 `src/config/site.ts` 的 `nav` 里加一项

## 三、本地怎么跑

```bash
cd ~/Projects/great-lakes-sports-website
npm install       # 只有第一次，或换了电脑时需要
npm run dev       # 打开 http://localhost:4321，改文件会自动刷新
npm run build     # 检查有没有错误（会先跑类型检查）
```

关掉开发服务器：`npx astro dev stop`

## 四、怎么发布

**`git push` 就是发布。**

```bash
git add -A
git commit -m "描述这次改了什么"
git push
```

推上去之后 Cloudflare 自动构建，**约 35 秒后线上生效**。不需要登录 Cloudflare 后台做任何事。

> 提交信息用英文，格式 `feat:` 新功能 / `fix:` 修问题 / `docs:` 改文档 / `refactor:` 重构 / `chore:` 杂项。这个仓库是公开的作品集，提交历史本身也是给人看的。

## 五、已经定过的决策（别推翻）

这些不是随手选的，改之前先想清楚为什么。

**1. 导航栏不用汉堡菜单。** 客群偏年长，把网站结构藏在一个图标后面，很多人不认识那是可以点的。只有三个链接，手机上直接换行显示就够了。

**2. 正文 17px、行高 1.75。** 比常见的 16px/1.5 大一档。相当一部分访客在五十岁以上。另外法文比英文平均长 15–20%，排版是流式的所以撑得住，但改版式时要留意这一点。

**3. 文案和代码分开。** 所有文字都在 `src/content/` 和 `src/i18n/`，页面模板里不写死任何一句话。这样师兄以后要自己改字时，接一个可视化后台就行，不用重构。**新增内容时请保持这个习惯。**

**4. 颜色只在 `global.css` 里定义一次。** 页面里用 `bg-forest-900` 这样的名字，**不要直接写 `#12392c`**。品牌微调时改一处，全站同步。

**5. GAG 标识是矢量画的，不是那些 JPG 效果图。** 客户给的是 AI 生成的排版稿：没有透明背景、位图会糊、颜色还前后不一致。矢量版能自动适应深浅底色（墨绿页脚上自动变象牙白），不到 1KB。那些 JPG 用在 Brand 页的图集里，那才是它们该待的地方。

**6. 不编造信息。** 没有的联系邮箱就写「即将公布」，不编一个假地址；客户只给了五个价值观名词，就好好排版这五个词，不替他编解释。**编出来的东西客户一眼能看出不是自己的意思，比留白更伤信任。**

**7. 网址不带结尾斜杠**（`/about` 而不是 `/about/`）。这样 canonical 标签、hreflang、站点地图里写的地址和实际访问的地址是同一个字符串，站内跳转也不用多绕一次。

**8. ⚠️ 网站语言只有英文和法文，不出现中文。** 这是客户 2026-08-09 明确的要求：品牌定位上不希望受众把公司和赛事与中国、华人做联接。加拿大是英法双语国家，法文版在安省有天然正当性（次要参考站 ovga.org 本身就是 en/fr 结构）。

**任何新增内容都必须同时提供英文和法文，不要加回中文。** 法文用加拿大惯例（如赞助用 commandite 而非 parrainage，地名写 Toronto (Ontario)），`hreflang` 用 `fr-CA` 而非 `fr`。

> 本文档本身是中文的工作笔记，不属于网站内容，网站也不引用它。**这一份保持中文**（方便我自己查阅），网站内容一律英法。

## 七、安全须知

**这个仓库是公开的，任何人都能看到全部代码和历史。**

- **绝对不要把这些提交进来**：公司注册文件、财务资料、合同、任何密钥或密码。`.gitignore` 里已经设了安全网（`*.docx` `*.pdf` `.env` 等一律拦截，并且实测验证过），但**最终把关的是提交前看一眼 `git status`**。
- **git 历史是永久的。** 文件一旦提交，后面再删也还留在历史里，任何人 clone 下来都能翻出来。所以是「提交前挡住」，不是「提交后再删」。
- 以后接了需要密钥的服务（邮件、支付、统计），密钥填在 Cloudflare 后台的环境变量里，**不写进代码**。
